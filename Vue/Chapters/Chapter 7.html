开发环境

Vue.js 核心特性

Vue.js 是一个渐进式 JavaScript 框架，具有以下核心特性：

  • 数据驱动视图 - 当数据变化时，视图自动更新
  • 插件系统 - 通过插件扩展功能（如Vue Router、Vuex）
  • 双向数据绑定 - v-model指令实现表单输入和应用状态的双向绑定
  • 指令系统 - 特殊的HTML属性（如v-if, v-for）

Vue 3 在底层做了重大改进（渲染、数据监听、双向绑定、生命周期等），但使用方式与 Vue 2 相似，易于学习和迁移。

单文件组件

什么是单文件组件？

单文件组件（Single File Components，SFC）是 Vue 的特色功能，它将一个组件的模板、逻辑和样式封装在一个 .vue 文件中。

每个 .vue 文件由三部分组成：

  1. <template> - 组件的 HTML 模板
  2. <script> - 组件的 JavaScript 逻辑
  3. <style> - 组件的 CSS 样式

这种组织方式使组件更易于维护和理解，所有相关代码都在一个文件中。

传统方式 vs 组件化方式

传统方式 组件化方式
依赖关系混乱，不易维护 清晰的组件依赖关系
代码复用率不高 高度可复用的组件
HTML/CSS/JS分离 HTML/CSS/JS在组件内统一管理
全局样式冲突 支持作用域样式

单文件组件结构

Demo.vue 组件示例
<template>
  <!-- 组件的 HTML 结构 -->
  <div class="demo">
    {{ message }}
  </div>
</template>

<script>
// 组件的 JavaScript 逻辑
export default {
  data() {
    return {
      message: '你好，Vue 单文件组件！'
    }
  }
}
</script>

<style scoped>
/* 组件的 CSS 样式 (scoped 表示只作用于当前组件) */
.demo {
  font-size: 1.2rem;
  color: #2c662d;
  padding: 20px;
  background-color: #e8f5e9;
  border-radius: 8px;
}
</style>

单文件组件语法总结

部分 语法 说明
模板部分 <template>...</template> 定义组件的HTML结构，使用Vue模板语法
脚本部分 <script>...</script> 定义组件的JavaScript逻辑，包括数据、方法等
样式部分 <style>...</style> 定义组件的CSS样式，可添加scoped属性限制作用域
组件导出 export default { ... } 导出组件配置对象（选项式API）
组合式API <script setup>...</script> 使用setup语法糖简化组合式API

关键点：

  • 每个.vue文件只定义一个组件
  • 使用scoped样式避免全局污染
  • 组合式API（Composition API）是Vue 3的推荐写法
  • 组件应保持单一职责原则，功能集中

组件使用示例

在 App.vue 中使用组件
<template>
  <div id="app">
    <h1>我的 Vue 应用</h1>
    <DemoComponent />  <!-- 使用 Demo 组件 -->
  </div>
</template>

<script>
// 导入 Demo 组件
import DemoComponent from './components/Demo.vue'

export default {
  // 注册组件
  components: {
    DemoComponent
  }
}
</script>

单文件组件的优势

1. 模块化：每个组件都是独立的单元，包含自己的模板、逻辑和样式。

2. 可复用性：组件可以在应用的不同部分重复使用。

3. 作用域CSS：使用 scoped 属性可以确保样式只应用于当前组件。

4. 预处理器支持：可以使用 Sass、Less 等 CSS 预处理器。

数据绑定

Vue 数据绑定基础

Vue 通过数据绑定实现了数据与视图的分离，实现了数据驱动视图的效果。

数据绑定分为两个主要部分：

  1. 定义数据 - 在组件的 script 部分定义数据
  2. 输出数据 - 在模板中使用 Mustache 语法（双大括号）输出数据

当数据改变时，视图会自动更新，无需手动操作 DOM。

响应式数据绑定

Vue 3 提供了多种创建响应式数据的方法：

方法 用途 特点
ref() 创建基本类型的响应式数据 通过 .value 访问/修改值
reactive() 创建对象的响应式副本 直接访问属性，无需 .value
toRef() 将响应式对象的属性转换为 ref 保持与源属性的响应式连接
toRefs() 将响应式对象转换为普通对象，其属性都是 ref 方便解构响应式对象

响应式API语法总结

API 语法 说明 适用场景
ref const count = ref(0) 创建基本类型响应式数据，通过.value访问 数字、字符串、布尔值等
reactive const state = reactive({ count: 0 }) 创建对象/数组响应式数据，直接访问属性 对象、数组等复杂数据结构
toRef const countRef = toRef(state, 'count') 将响应式对象的属性转为ref 单独传递响应式对象的属性
toRefs const { count, name } = toRefs(state) 将响应式对象解构为多个ref 解构响应式对象同时保持响应性

关键点：

  • ref适用于基本类型，reactive适用于对象类型
  • 模板中使用ref数据时无需.value，在JS中需要.value
  • toRefs在组合式函数返回响应式对象时非常有用
  • 避免同时使用ref和reactive处理同一数据源

ref() 函数示例

使用 ref() 创建响应式数据
<template>
  <div>
    <p>{{ message }}</p>
    <button @click="changeMessage">更改消息</button>
  </div>
</template>

<script setup>
import { ref } from 'vue'

// 创建响应式数据
const message = ref('初始消息')

// 更改数据的方法
function changeMessage() {
  message.value = '消息已更新！'
}
</script>

reactive() 函数示例

使用 reactive() 创建响应式对象
<template>
  <div>
    <p>姓名: {{ user.name }}</p>
    <p>年龄: {{ user.age }}</p>
    <button @click="updateUser">更新用户</button>

}

toRef() 和 toRefs() 函数示例

toRef() 和 toRefs() 使用
<template>
  <div>
    <h3>toRef 示例</h3>
    <p>原始对象: {{ state.count }}</p>
    <p>转换后的 ref: {{ countRef }}</p>
    
    <h3>toRefs 示例</h3>
    <p>姓名: {{ name }}</p>
    <p>年龄: {{ age }}</p>
    
    <button @click="updateData">更新数据</button>
  </div>
</template>

<script setup>
import { reactive, toRef, toRefs } from 'vue'

// toRef 示例
const state = reactive({ count: 0 })
const countRef = toRef(state, 'count')

// toRefs 示例
const userState = reactive({
  name: '王五',
  age: 28
})
const { name, age } = toRefs(userState)

function updateData() {
  // 修改源数据会更新 ref
  state.count++
  
  // 修改 ref 也会更新源数据
  countRef.value++
  
  // 修改解构后的 ref
  name.value = '赵六'
  age.value += 1
}
</script>
运行结果

原始对象: {{ state.count }}

转换后的 ref: {{ countRef }}

toRefs 示例

姓名: {{ name }}

年龄: {{ age }}

数据绑定语法总结

语法 示例 说明
Mustache语法 {{ message }} 在模板中显示响应式数据
v-bind指令 <div v-bind:class="className"> 动态绑定HTML属性
v-model指令 <input v-model="username"> 实现表单元素的双向绑定
v-if/v-show <div v-if="isVisible">...</div> 条件渲染，控制元素显示/隐藏
v-for指令 <li v-for="item in items" :key="item.id"> 列表渲染，循环生成元素

关键点：

  • Mustache语法内可以写简单的JavaScript表达式
  • v-bind可以简写为冒号：:class="className"
  • v-model在内部为不同输入元素使用不同属性并抛出不同事件
  • v-if是"真正"的条件渲染，v-show只是切换CSS的display属性
  • 使用v-for时总是提供key属性，以便Vue跟踪节点身份

Props属性

组件通信基础

Props 是父组件向子组件传递数据的主要方式，是组件通信的基础。

使用 Props 的步骤：

  1. 在子组件中声明 Props
  2. 在父组件中通过属性传递数据
  3. 在子组件中使用 Props 数据

Props 是单向数据流，父组件的数据变化会自动更新子组件，但子组件不能直接修改 Props。

Props语法总结

部分 语法 说明
声明Props props: ['title', 'content'] 数组形式声明Props（简单形式）
带类型检查 props: { title: String, count: Number } 对象形式声明Props，指定类型
完整声明 props: { title: { type: String, required: true } } 完整形式声明，包含类型、必需性、默认值等
传递Props <ChildComponent :title="pageTitle" /> 使用v-bind传递动态值
使用Props <h2>{{ title }}</h2> 在子组件模板中使用props数据

最佳实践：

  • 为每个prop指定类型，便于理解和调试
  • 为可选的prop提供默认值
  • 对于必须传递的prop，使用required: true
  • 避免在子组件内修改prop，使用data或computed属性代替
  • 使用camelCase声明prop，在模板中使用kebab-case

Props 使用示例

学生信息组件 (Student.vue)
<template>
  <div class="student">
    <h2>学生信息</h2>
    <p>姓名: {{ name }}</p>
    <p>性别: {{ sex }}</p>
    <p>年龄: {{ age }}</p>
  </div>
</template>

<script>
export default {
  // 声明 Props
  props: {
    name: String,
    sex: {
      type: String,
      default: '男'
    },
    age: {
      type: Number,
      required: true
    }
  }
}
</script>
在父组件中使用 (App.vue)
<template>
  <div id="app">
    <h1>学生管理系统</h1>
    <Student name="张三" sex="男" :age="18" />
    <Student name="李四" sex="女" :age="20" />
    <Student name="王五" :age="22" /> <!-- 使用默认性别 -->
  </div>
</template>

<script>
import Student from './components/Student.vue'

export default {
  components: {
    Student
  }
}
</script>

单页Web应用 (SPA)

什么是单页应用？

单页Web应用（Single Page Application, SPA）所有的功能局限于一个Web页面中，仅在该页面的初始化时加载相应的资源（HTML、CSS和JavaScript代码）。

在页面加载完成后，所有的操作都在这个页面上完成，不会因用户的操作而进行页面的重新加载或跳转，而是利用JavaScript动态地变换页面的内容。

SPA 的优势

良好的交互体验
内容的改变不需要重新加载整个页面，响应速度更快
前后端分离
后端专注于提供API，更容易实现API的复用
减轻服务器压力
数据通过Ajax获取，不需要重新加载页面

SPA与传统多页应用对比

特性 SPA 传统多页应用
页面加载 只加载一次页面 每次导航都加载新页面
用户体验 更流畅，页面切换无白屏 页面切换有刷新感
开发模式 前后端分离 通常耦合度更高
SEO优化 需要额外优化（SSR） 原生支持更好
技术栈 Vue, React, Angular等 传统服务器端渲染技术
首次加载 可能较慢（需加载所有资源） 通常较快（按需加载）

SPA开发要点：

  • 使用Vue Router实现前端路由
  • 通过API与后端交互获取数据
  • 使用状态管理（如Pinia/Vuex）管理共享状态
  • 考虑代码分割优化首次加载性能
  • 对SEO有要求的项目考虑SSR（服务器端渲染）

SPA 的工作原理

1
加载基础资源
浏览器加载HTML、CSS和JavaScript
2
初始化应用
Vue应用初始化，渲染初始视图
3
处理用户交互
用户操作触发JavaScript事件
4
动态更新内容
通过Ajax获取数据，动态更新DOM
5
更新URL
使用History API更新URL而不刷新页面

SPA 与传统多页应用的区别

1. 页面加载：SPA只加载一次页面，多页应用每次导航都加载新页面

2. 用户体验：SPA提供更流畅的用户体验，页面切换无白屏

3. 开发模式：SPA前后端分离，多页应用通常耦合度更高

4. SEO优化：传统多页应用更利于SEO，SPA需要额外优化
