数据库原理：第五章数据库完整性测验

深入了解数据库完整性的定义、类型、检查与违约处理！

一、单项选择题

1. 数据库完整性指的是数据的（　　）。

正确答案：B

解析： 数据库完整性是指数据的正确性（符合现实世界语义）和相容性（数据库中同一对象在不同关系表中的数据保持一致）。

2. 实体完整性规则规定，关系的主码（　　）。

正确答案：B

解析： 实体完整性是关系模型的三类完整性约束之一，它要求主码的每个属性都不能是空值（NOT NULL），并且主码值必须是唯一的（UNIQUE），以确保每个元组都能被唯一标识。

3. 在参照完整性中，当删除被参照表（父表）中的一个元组时，如果设定了 ON DELETE CASCADE 规则，则下列说法正确的是（　　）。

正确答案：C

解析： `ON DELETE CASCADE` 是一种参照完整性违约处理策略，它表示当被参照表中的父元组被删除时，参照表中所有引用该父元组的子元组也将被自动删除。

4. 用户定义的完整性主要是为了（　　）。

正确答案：C

解析： 用户定义的完整性是针对特定应用的业务规则和语义要求而设定的约束，例如某个属性的取值范围、特定属性之间的逻辑关系等，这些是实体完整性和参照完整性无法涵盖的。

5. 在 CREATE TABLE 语句中，CHECK 短语可以用于定义（　　）。

正确答案：C

解析：： `CHECK` 短语可以用来定义属性值满足的条件（如年龄大于0），也可以定义元组内不同属性值之间的相互约束（如性别为男则姓名不能以“Ms.”开头）。

6. 关于数据库触发器（Trigger），下列说法不正确的是（　　）。

正确答案：B

解析：： 触发器只能定义在**基本表**上，不能定义在视图上。视图是虚拟的表，不存储数据，因此无法直接在其上定义触发器。

7. 在参照完整性中，如果被参照表（父表）的主码值被修改或删除，子表的外码被设置为NULL，这种策略是（　　）。

正确答案：D

解析：： `SET NULL` 策略是指当删除或修改被参照表的一个元组时，将参照表中所有导致不一致的元组的对应外码属性设置为空值。前提是外码列允许为空。

8. 为完整性约束指定名称的主要好处是（　　）。

正确答案：B

解析：： 通过 `CONSTRAINT <完整性约束名>` 语法为约束命名后，可以使用 `ALTER TABLE ... DROP CONSTRAINT <完整性约束名>` 语句方便地删除或修改这些约束，无需记住其复杂的定义内容。

9. 如果一个触发器被定义为 BEFORE INSERT，那么它的触发动作体将在（　　）执行。

正确答案：A

解析：： `BEFORE` 触发器表示在触发事件（如 `INSERT`、`UPDATE`、`DELETE`）的操作执行**之前**激活触发器。这允许在数据被实际修改前进行校验或预处理。

10. 对于一个 UPDATE 语句影响了100行数据，如果定义了一个 FOR EACH STATEMENT 触发器，那么该触发器会执行（　　）次。

正确答案：B

解析：： `FOR EACH STATEMENT` 是语句级触发器，意味着无论SQL语句影响了多少行，触发动作体只在整个SQL语句执行完毕后**执行一次**。而 `FOR EACH ROW`（行级触发器）则会执行与受影响行数相同的次数。

二、填空题

1. 数据库的完整性包括数据的正确性和。

正确答案： 相容性

解析：： 完整性是数据应符合现实世界语义（正确性）和数据库内部数据之间的一致性（相容性）。

2. 关系数据库管理系统通常在执行 INSERT、UPDATE、DELETE 语句开始检查完整性约束。

正确答案： 之后

解析：： 完整性检查通常在数据操作（增删改）执行后进行，以验证操作是否破坏了预定义的约束。部分系统也支持在事务提交时检查。

3. 如果主码由多个属性构成，则只能在 CREATE TABLE 语句的定义主码。

正确答案： 表级

解析：： 单属性主码可以在列级或表级定义，但复合主码（由多个属性组成）必须在表级定义，因为它们涉及到多个列的组合约束。

4. FOREIGN KEY 短语用于定义外码，而 REFERENCES 短语用于指明这些外码参照哪个表的主码，被参照的表称为。

正确答案： 父表

解析：： 在参照完整性中，包含外码的表称为参照表（或子表），而被外码引用的表（包含主码）称为被参照表（或父表）。

5. 触发器是实现事件-条件-规则（ECA规则）的数据库对象。

正确答案： 动作

解析：： ECA规则是事件驱动系统（包括触发器）的核心，指当特定事件发生时，如果满足某个条件，则执行相应的动作。

三、判断题

1. 数据库的完整性旨在防止非法用户和非法操作，而安全性则防止不符合语义的数据进入数据库。

正确答案：错误

解析：： 题干混淆了完整性和安全性的定义。完整性是防止不合语义或不正确的数据，而安全性是保护数据库防止恶意的破坏和非法存取。

2. 在SQL中，如果未显式指定参照完整性的违约处理策略，默认是 NO ACTION（拒绝执行）。

正确答案：正确

解析：： SQL标准规定，如果未指定 `ON DELETE` 或 `ON UPDATE` 的行为，默认的参照完整性违约处理是 `NO ACTION`（或 `RESTRICT`），即拒绝执行可能破坏完整性的操作。

3. UNIQUE 约束不允许列中出现重复值，但允许出现多个 NULL 值。

正确答案：正确

解析：： `UNIQUE` 约束确保非NULL值的唯一性。根据SQL标准，NULL值被视为不等于任何其他值（包括其他NULL值），因此允许在一列中存在多个NULL值，除非同时定义了 `NOT NULL` 约束。

4. 触发器是一种特殊的存储过程，因此可以像调用其他存储过程一样显式调用触发器。

正确答案：错误

解析：： 触发器是事件驱动的，由数据库服务器在特定事件（如INSERT, UPDATE, DELETE）发生时自动激活，不能被用户直接显式调用。它是特殊的存储过程，但其调用方式与普通存储过程不同。

5. 在行级触发器的触发动作体中，可以使用 NEW 和 OLD 关键字来引用更新操作后的新值或操作前的旧值。

正确答案：正确

解析：： 行级触发器可以访问受操作影响的每一行的旧值（`OLD`）和新值（`NEW`），这使得可以编写更精细的逻辑来比较或操作数据在变化前后的状态。语句级触发器则不能使用这两个关键字。

四、SQL编程题

1. **请写出SQL语句，创建一个名为 CourseOffering 的表，包含 CourseID, Semester 和 Year 字段，其中 (CourseID, Semester, Year) 组合作为主码。**

参考答案：

CREATE TABLE CourseOffering (
    CourseID CHAR(5),
    Semester CHAR(10),
    Year SMALLINT,
    PRIMARY KEY (CourseID, Semester, Year) -- 复合主码，必须在表级定义
);

解析：

  1. 使用 `CREATE TABLE` 语句定义新表 `CourseOffering`。
  2. 包含所有指定列及其数据类型。
  3. 由于主码由多个属性组成 (`CourseID`, `Semester`, `Year`)，因此必须在表级使用 `PRIMARY KEY (column1, column2, ...)` 语法进行定义。

2. **假设存在 Department 表（DeptID 是主码）。请写出SQL语句，创建一个 Professor 表，包含 ProfID (主码), ProfName 和 DeptID。其中，DeptID 是外码，参照 Department 表的 DeptID。要求：当 Department 表中的部门被删除时，级联删除 Professor 表中对应的教授记录；当 Department 表中的 DeptID 被更新时，级联更新 Professor 表中对应的 DeptID。**

参考答案：

-- 假设 Department 表已存在
-- CREATE TABLE Department (DeptID CHAR(3) PRIMARY KEY, DeptName VARCHAR(50));

CREATE TABLE Professor (
    ProfID CHAR(4) PRIMARY KEY,
    ProfName VARCHAR(50) NOT NULL,
    DeptID CHAR(3),
    FOREIGN KEY (DeptID) REFERENCES Department(DeptID)
        ON DELETE CASCADE -- 当部门被删除时，级联删除教授
        ON UPDATE CASCADE -- 当部门ID被更新时，级联更新教授的部门ID
);

解析：

  1. 使用 `FOREIGN KEY (DeptID) REFERENCES Department(DeptID)` 定义外码关系。
  2. `ON DELETE CASCADE` 指定当父表 `Department` 的元组被删除时，子表 `Professor` 中所有引用该元组的记录也一并删除。
  3. `ON UPDATE CASCADE` 指定当父表 `Department` 的 `DeptID` 被更新时，子表 `Professor` 中所有引用该 `DeptID` 的记录的 `DeptID` 也一并更新。

3. **请写出SQL语句，创建一个 StudentScores 表，包含 StudentID (主码), CourseID 和 Score 字段。要求 Score 字段的值必须在 0 到 100 之间（包含0和100）。**

参考答案：

CREATE TABLE StudentScores (
    StudentID CHAR(8),
    CourseID CHAR(5),
    Score SMALLINT CHECK (Score >= 0 AND Score <= 100), -- 成绩范围约束
    PRIMARY KEY (StudentID, CourseID)
);

解析：：

  1. 使用 `CREATE TABLE` 定义表结构。
  2. 在 `Score` 列定义后面添加 `CHECK (Score >= 0 AND Score <= 100)` 来指定分数必须在有效范围内。

4. **请写出SQL语句，创建一个名为 Employee 的表，包含 EmpID (主码), EmpName 和 Salary 字段。为 Salary 字段添加一个名为 CK_SalaryRange 的约束，要求工资必须大于 0。然后，写出SQL语句，将此约束修改为要求工资必须大于 1000。**

参考答案：

-- 创建表并定义命名约束
CREATE TABLE Employee (
    EmpID CHAR(5) PRIMARY KEY,
    EmpName VARCHAR(50) NOT NULL,
    Salary NUMERIC(10,2)
        CONSTRAINT CK_SalaryRange CHECK (Salary > 0)
);

-- 修改约束：先删除原约束，再添加新约束
ALTER TABLE Employee
DROP CONSTRAINT CK_SalaryRange;

ALTER TABLE Employee
ADD CONSTRAINT CK_SalaryRange CHECK (Salary > 1000);

解析：

  1. 使用 `CONSTRAINT CK_SalaryRange CHECK (Salary > 0)` 在 `CREATE TABLE` 时为工资范围约束命名。
  2. 修改约束通常需要分两步：先使用 `ALTER TABLE ... DROP CONSTRAINT <约束名>` 删除旧约束。
  3. 然后使用 `ALTER TABLE ... ADD CONSTRAINT <约束名> <新约束定义>` 添加新的约束。

5. **请写出SQL语句，定义一个名为 CheckStudentMajor 的 BEFORE INSERT 行级触发器，作用于 Student 表。当插入新的学生记录时，如果学生的 Smajor 属性（专业）是 '计算机科学与技术'，并且学生的学号 Sno 以 '2' 开头，则将其 Smajor 自动改为 '软件工程'。**

参考答案：

CREATE TRIGGER CheckStudentMajor
BEFORE INSERT ON Student -- BEFORE INSERT 触发器，作用于Student表
REFERENCING NEW AS newTuple -- 定义newTuple来引用新插入的行数据
FOR EACH ROW -- 行级触发器
WHEN (newTuple.Smajor = '计算机科学与技术' AND newTuple.Sno LIKE '2%') -- 触发条件
BEGIN
    newTuple.Smajor := '软件工程'; -- 触发动作：修改Smajor为'软件工程'
END;

解析：

  1. `CREATE TRIGGER CheckStudentMajor` 定义触发器名称。
  2. `BEFORE INSERT ON Student` 指定在 `Student` 表执行 `INSERT` 操作**之前**触发。
  3. `REFERENCING NEW AS newTuple` 允许在触发器中通过 `newTuple` 访问即将插入的新行的数据。
  4. `FOR EACH ROW` 指定这是一个行级触发器，对每一行受影响的数据都会执行一次。
  5. `WHEN (...)` 定义了触发条件：当新行的专业是'计算机科学与技术'且学号以'2'开头时。
  6. `BEGIN ... END;` 包裹触发动作体，其中 `newTuple.Smajor := '软件工程';` 会在实际插入前修改 `Smajor` 的值。
