一、基本概念

掌握数据库核心理论，理解关键术语

1. 数据库系统的组成,核心。

答案: 数据库系统 (DBS) 主要由 数据库 (DB)、数据库管理系统 (DBMS)、数据库管理员 (DBA)、和应用系统 组成。其中，数据库管理系统 (DBMS) 是核心。

2. 数据库三级模式的定义(一句话),个数。

答案: 数据库三级模式包括：外模式（用户视图）、模式（全局逻辑视图）和内模式（物理存储视图）。共有 3个 模式。

3. 数据库的物理独立性、逻辑独立性。(和三级模式的关系)。

答案:

  • 物理独立性: 指当数据库的内模式（物理存储结构）改变时，模式和外模式不需要改变。它依赖于内模式与模式之间的映射。
  • 逻辑独立性: 指当数据库的模式（全局逻辑结构）改变时，外模式和应用程序不需要改变。它依赖于外模式与模式之间的映射。

4. 在关系模型中,二维表、行,列的定义。

答案:

  • 二维表 (关系/Relation): 具有特定结构的数据集合，由行和列组成，表示实体和实体之间的联系。
  • 行 (元组/Tuple): 表中的一条记录，对应关系中的一个元组，表示一个实体或一个联系的实例。
  • 列 (属性/Attribute): 表中的一个字段，对应关系中的一个属性，表示实体或联系的某一特性。

5. 数据库系统中,数据的最小存取单位。

答案: 在数据库系统中，数据的最小存取单位是字段（或属性值）。对于物理存取，最小单位通常是块或页。

6. 主码和外码的描述。

答案:

  • 主码 (Primary Key): 能够唯一标识关系中每一个元组（行）的属性或属性组。主码的值必须唯一且非空。
  • 外码 (Foreign Key): 一个关系中的一个属性或属性组，它的值参照（匹配）另一个关系的主码的值。外码用于建立和维护不同关系之间的联系。

7. 关系代数: 已知学生表为学生(学号,姓名,性别,出生日期,专业编号),专业表为 专业(专业编号,名称)。

查询姓名为XX的出生日期的关系代数。

答案: Π出生日期 ( σ姓名='XX' (学生) )

答案: Π姓名 (学生 ⨭学生.专业编号=专业.专业编号 ( σ名称='YY' (专业) ) )

答案: Π姓名 ( σ性别='男' (学生) ) 或 Π姓名 ( σ性别='女' (学生) ) (具体取决于*代表的性别)

答案: Π名称 (学生 ⨭学生.专业编号=专业.专业编号 ( σ姓名='XX' (学生) ) )

8. 完整性约束(3个),完整性约束使用的关键字(主码、外码、唯一、非空、检查)。

答案:

  • 实体完整性: 规定关系的主码不能为空（NOT NULL）且唯一（PRIMARY KEY，隐含唯一）。
  • 参照完整性: 规定外码的值要么为空，要么必须匹配其参照关系的主码的值（FOREIGN KEY）。
  • 用户定义完整性: 根据实际应用需求定义的约束，例如某个属性的取值范围（CHECK）、唯一性约束（UNIQUE）等。

9. 参照完整性的定义。

答案: 参照完整性（Referential Integrity）是指如果关系中的某个属性或属性组是外码，则它的值必须在它所参照的父关系的主码中存在，或者该外码的所有组成属性都为空值。

10. 创建表的语句。

创建订单(orders)表的语句如下,按要求把相关语句补充完整。 

CREATE TABLE orders (
    order_id INT PRIMARY KEY,
    user_id INT NOT NULL,
    order_date DATETIME DEFAULT CURRENT_TIMESTAMP,
    total_amount DECIMAL(10,2),
    FOREIGN KEY (user_id) REFERENCES users(user_id)
);

创建选课表(course_selection)的语句如下,按要求把相关语句补充完整。(1)选课日期(属性名)数据类型为日期型,且非空; (2)主码为学号(student_id)和课程号(course_id)的组合。 

CREATE TABLE course_selection (
    student_id INT,
    course_id INT,
    enrollment_date DATE NOT NULL,
    PRIMARY KEY (student_id, course_id)
);

11. 修改表定义的命令,可以修改什么。Alter Table.

答案: 修改表定义的命令是 ALTER TABLE。它可以修改表的结构，包括：

  • 添加/删除列 (ADD/DROP COLUMN)
  • 修改列的数据类型、大小或约束 (ALTER COLUMN/MODIFY COLUMN)
  • 添加/删除约束 (ADD/DROP CONSTRAINT，如PRIMARY KEY, FOREIGN KEY, UNIQUE, CHECK)
  • 重命名表或列 (RENAME TO/RENAME COLUMN)

12. 删除表定义的命令。Drop Table (Delete)

答案: 删除表定义的命令是 DROP TABLE。它会删除表的结构和所有数据。
而 DELETE FROM 命令是删除表中的数据，但不删除表结构。

13. 查询语句中,关键字 Select、From、Where、Group By、Having、Order By 的作用。

答案:

  • SELECT: 指定要查询的列或表达式。
  • FROM: 指定要从中检索数据的表或视图。
  • WHERE: 用于筛选行，指定满足条件的行才会被返回。
  • GROUP BY: 将查询结果按照一个或多个列进行分组，通常与聚合函数一起使用。
  • HAVING: 对 GROUP BY 分组后的结果进行筛选，条件中可以使用聚合函数。
  • ORDER BY: 对查询结果进行排序（升序ASC或降序DESC）。

14. LIKE 查询通配符的含义(%,_)。

答案: 在 LIKE 子句中使用的通配符：

  • % (百分号): 代表任意长度（0个或多个）的任意字符。
  • _ (下划线): 代表单个任意字符。

15. 连接操作的含义(等值连接、自然连接)。

答案: 连接操作用于将两个或多个关系（表）根据它们之间的共同属性（列）连接起来，生成一个新的关系。

  • 等值连接 (Equijoin): 连接两个表中相等属性值的行。结果中通常包含重复的连接属性列。
  • 自然连接 (Natural Join): 是一种特殊的等值连接，它自动找出两个表中所有相同的属性列，并基于这些列进行等值连接，结果中只保留一个连接属性列（消除重复列）。

16. 常用的聚集函数(Count两个)。

答案: 常用的聚集函数（Aggregate Functions）包括：

  • COUNT(*): 统计行数（包括NULL值）。
  • COUNT(列名): 统计指定列中非NULL值的行数。
  • SUM(列名): 计算指定列的总和。
  • AVG(列名): 计算指定列的平均值。
  • MAX(列名): 获取指定列的最大值。
  • MIN(列名): 获取指定列的最小值。

17. Exists 子查询定义(不要求写程序)。

答案: EXISTS 子查询用于检查子查询是否返回了任何行。如果子查询返回至少一行，EXISTS 条件为真；如果子查询没有返回任何行，EXISTS 条件为假。它只关心是否存在行，而不关心返回的具体数据。

18. 集合操作的命令(并、交、差)。

答案: 集合操作用于对两个或多个查询结果进行组合，要求所有参与查询的列数和对应列的数据类型必须兼容。

  • 并集 (UNION): 返回两个查询结果的所有不重复的行。
  • 交集 (INTERSECT): 返回两个查询结果中共同存在的行。
  • 差集 (EXCEPT 或 MINUS): 返回第一个查询结果中存在但第二个查询结果中不存在的行。

19. 索引的作用,什么情况下需要建立索引。

答案:

  • 索引的作用: 索引是提高数据库查询速度的有效方式，类似于书的目录。它通过创建快速数据查找路径，减少数据库系统扫描的数据量，从而加快数据检索速度。
  • 建立索引的情况:
    • 经常在 WHERE 子句中使用的列。
    • 经常在 JOIN 操作中连接的列（外码）。
    • 经常在 ORDER BY、GROUP BY 子句中使用的列。
    • 主码和唯一约束列（通常会自动创建索引）。
    • 表中数据量大，查询性能要求高。

20. 视图的定义,如何修改视图的定义(关键字),视图更新的要求。

答案:

  • 视图的定义: 视图是一个虚拟的表，其内容由查询定义。它不存储实际数据，而是基于一个或多个基本表的数据动态生成。视图提供了一种逻辑上的数据访问方式，可以简化复杂查询、提高数据安全性。
  • 修改视图的定义: 使用 ALTER VIEW 或先 DROP VIEW 再 CREATE VIEW。
  • 视图更新的要求: 只有当视图的定义满足一定条件时，才能对视图进行更新（INSERT, UPDATE, DELETE）。通常，可更新视图需要满足以下条件：
    • 视图的查询定义只涉及一个基本表。
    • 视图中包含基本表的所有非空列。
    • 视图中不包含聚合函数、DISTINCT、GROUP BY、HAVING 子句。
    • 视图中不包含 UNION、INTERSECT、EXCEPT 等集合操作。

21. 1NF、2NF、3NF的定义。

答案:

  • 第一范式 (1NF): 关系中的所有属性都是不可再分的原子值。即不允许在关系中出现重复的组（嵌套关系）。
  • 第二范式 (2NF): 在满足 1NF 的基础上，非主属性完全函数依赖于主码（即不存在部分函数依赖）。
  • 第三范式 (3NF): 在满足 2NF 的基础上，非主属性不传递函数依赖于主码（即不存在传递函数依赖）。

22. 在SQL中,授予权限和撤销权限的命令。

答案:

  • 授予权限: GRANT
  • 撤销权限: REVOKE

答案:

26. 数据库设计的阶段,每个阶段的任务。

答案: 数据库设计通常分为以下几个阶段：

  • 需求分析: 收集、分析用户的数据需求和功能需求。形成数据字典和数据流图。
  • 概念结构设计: 抽象、概括数据，形成独立于具体DBMS的概念模型。主要任务是绘制 E-R 图。
  • 逻辑结构设计: 将概念模型转换为特定 DBMS 所支持的数据模型（如关系模型），并进行范式化处理。
  • 物理结构设计: 为逻辑数据模型选择合适的物理存储结构和存取方法，如确定文件组织方式、建立索引等。
  • 数据库实施: 根据设计结果，使用 DDL 语言建立数据库模式，装载数据，并编写应用程序。
  • 数据库运行和维护: 数据库的日常运行、性能监控、备份恢复、安全管理和系统优化等。

27. 在E-R 模型中,一对一、一对多、多对多联系转换为关系模型的方法(合并? 独立?)。

答案:

  • 1:1 联系:
    • 合并: 将联系属性和任意一个实体的主码合并到另一个实体对应的关系模式中（作为外码）。
    • 独立: 单独创建一个关系模式，其主码由参与联系的两个实体的主码构成，并包含联系属性。
  • 1:N 联系:
    • 合并: 在 N 端实体对应的关系模式中加入 1 端实体的主码作为外码，并包含联系属性。
  • M:N 联系:
    • 独立: 单独创建一个关系模式。该关系模式的主码由参与联系的两个实体的主码构成，并包含联系属性。

28. 日志文件的定义。

答案: 日志文件（Log File）是数据库管理系统用于记录所有事务操作的日志信息的文件。这些信息包括事务的开始、结束、对数据库的每一次更新操作（如修改前的值、修改后的值、操作时间等），主要用于数据库的恢复（如回滚、前滚）和并发控制。

29. 数据库恢复:备份(不同的备份方法:完全、增量)+日志。

答案: 数据库恢复是指将数据库从故障状态恢复到一致性状态。主要依赖于备份和日志文件。

  • 备份:
    • 完全备份 (Full Backup): 备份所有数据，耗时最长，但恢复最快。
    • 增量备份 (Incremental Backup): 备份自上次任何类型备份以来所有改变的数据。恢复时需要最近一次完全备份和所有后续的增量备份。
  • 日志文件: 记录了所有事务的操作，用于在恢复时进行重做（Redo）和撤销（Undo）操作，以确保数据的一致性。

30. 事务的 ACID 特性,每个特性的含义(一句话)。

答案: 事务的 ACID 特性是数据库系统保证事务正确执行的四个基本要素：

  • 原子性 (Atomicity): 事务是一个不可分割的工作单元，要么全部执行成功，要么全部不执行（回滚）。
  • 一致性 (Consistency): 事务执行前后，数据库从一个一致性状态转换到另一个一致性状态，保持数据的完整性约束。
  • 隔离性 (Isolation): 多个并发事务执行时，一个事务的执行不被其他事务干扰，就像是独立地执行一样。
  • 持久性 (Durability): 事务一旦提交成功，它对数据库的改变就是永久的，即使系统发生故障也不会丢失。

31. 在封锁协议中,X锁和S锁的定义。

答案: 在数据库的封锁协议中，X锁（排它锁/Exclusive Lock）和S锁（共享锁/Shared Lock）是两种基本的锁类型：

  • S锁 (共享锁/读锁): 如果事务 T 对数据对象 A 加上 S 锁，则其他事务可以对 A 加 S 锁，但不能加 X 锁。主要用于读操作，允许多个事务并发读取同一数据。
  • X锁 (排它锁/写锁): 如果事务 T 对数据对象 A 加上 X 锁，则其他事务不能对 A 加任何类型的锁。主要用于写操作，保证在修改数据时不会有其他事务同时读写。

32. 数据库并发操作中,三种不一致(丢失修改、脏读、不可重复读)的原因。并发控制的主要技术:封锁、时间戳、乐观方法、多版本并发控制。

答案: 数据库并发操作中可能出现的三种不一致性：

  • 丢失修改 (Lost Update): 一个事务的更新被另一个事务的更新覆盖，导致前一个事务的修改丢失。原因是没有足够的并发控制机制（如锁）来保护更新操作。
  • 脏读 (Dirty Read): 一个事务读取了另一个未提交事务的数据，如果后一个事务回滚，则前一个事务读取到的数据就是“脏”数据，不应该存在。
  • 不可重复读 (Non-repeatable Read): 一个事务在同一查询中多次读取同一数据，但每次读取到的数据不同，因为在两次读取之间有另一个事务修改并提交了数据。

并发控制的主要技术:
  • 封锁 (Locking): 通过对数据对象加锁来控制并发访问，防止冲突。
  • 时间戳 (Timestamp): 给事务或数据项赋予时间戳，基于时间戳的顺序来解决冲突。
  • 乐观方法 (Optimistic Concurrency Control): 假定冲突很少发生，在事务提交时才检查冲突，如果发现冲突则回滚。
  • 多版本并发控制 (Multi-Version Concurrency Control, MVCC): 为每个被修改的数据项创建多个版本，读事务可以访问旧版本，写事务创建新版本，从而实现读写不冲突。

(一) 规范化设计

1. 已知关系模式: 订单表(订单号,客户号,日期,产品号,产品名,单价,数量,总价) 函数依赖为: 订单号 → 客户号、日期； 产品号 → 产品名、单价； (订单号,产品号) → 数量、总价

(1) 写出订单表的主码。

答案: 订单表的主码是 (订单号, 产品号)。

(2) 订单表满足第几范式?为什么?

答案: 订单表满足第一范式 (1NF)。因为所有属性都是原子性的，没有重复组。
但是，它不满足第二范式 (2NF)。原因在于存在部分函数依赖：

  • 订单号 → 客户号、日期 (订单号是主码的一部分，但客户号和日期只依赖于订单号)
  • 产品号 → 产品名、单价 (产品号是主码的一部分，但产品名和单价只依赖于产品号)

(3) 将订单表规范到3NF,并用下划线画出主码。

答案: 规范到3NF的关系模式：

  • 订单 (订单号, 客户号, 日期)
  • 产品 (产品号, 产品名, 单价)
  • 订单明细 (订单号, 产品号, 数量, 总价)

2. 已知关系模式: 订单表(订单号,客户号,日期,产品号,产品名,单价,数量,总价) 函数依赖为: 订单号 → 客户号、日期； 产品号 → 产品名、单价； (订单号,产品号) → 数量、总价

四、考试技巧

高效备考，自信应答

为了帮助您更好地准备期末考试，以下是一些实用的备考建议：

  • 扎实基础: 深入理解数据库基本概念，如DBS组成、三级模式、两级独立性、范式定义等。这是所有进阶知识的基础。
  • 熟练SQL: 数据库考试中SQL编程是重中之重。务必多练习SQL查询、插入、更新、删除语句，尤其是连接查询、子查询、聚合函数和集合操作。掌握各种子句（SELECT, FROM, WHERE, GROUP BY, HAVING, ORDER BY）的作用及其执行顺序。
  • ER图与规范化: 彻底理解ER图的绘制规则（实体、属性、联系及其类型）和将ER图转换为关系模式的方法（特别是1:1, 1:N, M:N联系的转换）。熟悉范式理论（1NF, 2NF, 3NF）及如何将关系模式规范到3NF，这是设计题的考点。
  • 事务与并发控制: 掌握ACID特性及其含义。了解数据库并发操作中可能出现的各种不一致性问题（丢失修改、脏读、不可重复读）以及相应的并发控制技术（封锁、时间戳、乐观方法、MVCC）。
  • 权限管理: 熟悉`GRANT`和`REVOKE`命令的语法和用途，以及角色的创建和分配，这部分内容通常以填空或选择题形式考察。
  • 真题演练: 如果有条件，务必练习历年考题。通过做真题，可以熟悉题型和出题思路，提高解题速度和准确性。注意总结常考的知识点和易错点。
  • 时间管理: 考试时合理分配时间，先做自己最有把握的题目，再攻克难题。确保所有题目都有所作答，即使不确定也要尝试写出部分答案。
  • 审题仔细: 仔细阅读题目要求，特别是程序题和设计题。理解题目意图是正确解题的第一步，避免因粗心导致失分。
