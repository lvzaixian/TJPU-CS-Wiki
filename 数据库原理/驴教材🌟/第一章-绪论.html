1.1 数据库系统概述

重要程度:

1.1.0 数据管理技术的产生和发展 了解内容

数据管理技术经历了从人工管理、文件系统到数据库系统的发展过程。数据库系统阶段的核心特征是数据结构化、高共享性与低冗余度、高数据独立性以及由DBMS统一管理控制。

1.1.1 数据库的4个基本概念 必考核心

1. 数据 (Data)

定义: 描述事物的符号记录，是数据库中存储的基本对象。数据的含义称为语义，数据与其语义不可分。

  • 比如数字“93”，单独看只是个数字。但如果告诉你这是“张三的考试分数”，那它就有了明确的意义。在数据库里，数据总是和它的含义绑定在一起的。

2. 数据库 (DataBase, DB)

定义: 长期存储在计算机内、有组织、可共享的大量数据的集合。

基本特征：

  • 数据按一定数据模型组织、描述和存储
  • 较小的冗余度
  • 较高的数据独立性
  • 可扩展性
  • 数据库就像一个巨大的、分类清晰的“电子文件柜”。它不是简单地把数据堆在一起，而是有条理地整理好，方便大家一起使用和查找。

3. 数据库管理系统 (DBMS) ⭐ (4次真题出现)

定义: 位于用户与操作系统之间的一层数据管理软件，是计算机的基础软件和现代信息系统核心。

主要功能：

  • 数据定义功能 (DDL): 负责建立、修改、删除数据库中的对象结构，如创建表格、定义字段类型。
    • 就像图书管理员规划图书馆的布局，决定有多少个书架、每个书架放什么类型的书。
  • 数据操纵功能 (DML): 对数据库中的数据进行查询、插入、删除、修改操作。
    • 读者在图书馆里“找书”（查询）、“借新书”（插入）、“还书”（删除）、“更新书目信息”（修改）。
  • 数据组织、存储与管理功能: 管理数据在磁盘上的存放位置、存储结构和存取方式。
    • 图书馆员知道每本书具体放在哪个书架的哪个位置，并保证书籍摆放整齐方便查找。
  • 事务管理和运行管理功能: 保证数据的安全性、完整性、多用户并发使用和故障恢复。
    • 确保图书馆的规则得到遵守（例如，每人借书有上限），处理多个读者同时借阅同一本书的情况，以及在突发事件（如停电）后能恢复到正常状态。
  • 数据库的建立与维护功能: 初始数据输入、数据转储、性能监视等。
    • 新书入库登记、定期备份书目、检查读者查找书籍的速度是否够快。

4. 数据库系统 (DBS) ⭐

定义: 由数据库、DBMS(及外围应用开发工具)、应用程序、数据库管理员组成的计算机系统。

DBS管理数据的特点：

  • 整体数据的结构化: 数据不再是零散的，而是按照预设的规则组织起来，形成一个相互关联、有逻辑的整体。比如学生信息、课程信息、选课信息是相互连接的。
  • 数据的共享性强，冗余度低且易于扩充: 多个人或程序可以同时访问和使用同一份数据，大大减少了数据的重复存储，也更容易增加新的数据。
  • 数据的独立性强 (物理独立性、逻辑独立性): 这是数据库最重要的特点之一。简单来说，就是数据的存储方式或逻辑结构发生变化时，上层使用这些数据的应用程序不需要跟着修改。
  • 数据由DBMS统一管理和控制: 所有的数据库操作都由DBMS来负责，它会确保数据的安全（不被未授权的人看到或修改）、完整（数据是正确有效的）、并发控制（多个人同时操作也不会出错）、故障恢复（系统出问题后数据能恢复）。

数据的最小存取单位 ⭐ (0次真题出现)

  • 在数据库逻辑层面，数据的最小存取单位是字段（或属性值）。
    • 你通常查找或操作的是表格中的一个具体单元格内容，比如一个学生的“姓名”或“年龄”。
  • 在数据库物理存储层面，最小存取单位通常是块或页。
    • 电脑硬盘存储数据时，不会一个字节一个字节地读写，而是一次性读写一个固定大小的“数据块”。

1.2 数据模型

重要程度:

1.2.1 数据模型的概念、要素与分类 了解内容

1. 数据模型的基本概念

数据模型是数据库中用来抽象、表示和处理数据及数据间联系的工具。它通常包括三个部分：数据结构、数据操作和完整性约束。

2. 数据模型的要素

  • **数据结构 (Data Structure):** 描述数据的组织方式，如表、树、图等。
  • **数据操作 (Data Operation):** 允许对数据进行的操作集合，如查询、插入、删除、修改。
  • **完整性约束 (Integrity Constraints):** 规定了数据必须满足的条件，以保证数据的正确性和一致性。

3. 数据模型的分类

  • **概念模型 (Conceptual Model):** 用于信息世界的建模，如ER模型。
  • **逻辑模型 (Logical Model):** 用于数据库系统的实现，如关系模型、层次模型、网状模型。
  • **物理模型 (Physical Model):** 描述数据在存储介质上的组织结构和存取方法。

1.2.2 概念模型 (E-R模型) ⭐ (高频考点)

概念模型是数据库设计的第一步，用来抽象和描述现实世界中的信息。ER模型是表示概念模型的常用方法。

基本概念：

  • 实体 (Entity): 客观存在并可相互区别的事物，可以是具体的人、事、物或抽象概念。
    • 你要管理“学生”和“课程”的信息，那么“学生”和“课程”就是实体。
  • 属性 (Attribute): 实体所具有的特性。
    • “学生”有什么特点？有“学号”、“姓名”、“班级”等，这些就是属性。
  • 码 (Key): 唯一标识实体的属性集。
    • “学号”可以唯一确定一个学生，所以它是学生实体的一个“码”。
  • 联系 (Relationship): 现实世界中事物内部以及事物之间的关联。
    • 实体内部的联系: 组成实体的各属性之间的联系。
    • 实体之间的联系: 不同实体集之间的联系，分为一对一(1:1), 一对多(1:N), 多对多(M:N)。
      • “学生”和“课程”之间有“选课”的联系。如果一个学生能选多门课，一门课能被多个学生选，那就是“多对多”联系。

ER图的绘制: 使用矩形表示实体，椭圆形表示属性，菱形表示联系。通过连线和基数（如1、N、M）来表示联系类型。

  • 想象一下，画一个方框代表“学生”，方框外面引出圆圈代表“学号”、“姓名”等；再画一个方框代表“课程”，然后用一个菱形连接“学生”和“课程”，菱形里写“选课”，连接线上标明数量关系。

1.2.3 层次模型 了解内容

层次模型用树形结构表示数据及其联系，数据记录是节点，记录间的联系是边。其特点是每个子节点只有一个父节点。

  • 优点：结构清晰，查询效率高（尤其是对一对多关系），安全性好。
  • 缺点：对多对多关系支持不佳，数据冗余，查询复杂（需要预先定义访问路径）。

1.2.4 网状模型 了解内容

网状模型允许一个子节点有多个父节点，形成网状结构，比层次模型更灵活。

  • 优点：能直接表示一对多和多对多关系，提高了查询效率，减少了数据冗余。
  • 缺点：结构复杂，查询困难，应用程序对数据结构变化敏感。

1.2.5 关系数据模型 了解内容

关系数据模型是最重要、最广泛应用的一种逻辑数据模型。它使用二维表格（关系）来表示数据，以及表格之间的逻辑联系。这是第二章的核心内容。

1.2.6 关系模型 ⭐ (必考核心, 2次真题出现)

关系模型是目前最主流的数据模型，它把所有数据都组织成一张张相互关联的二维表格。

核心概念：

  • 关系 (Relation): 就是一张二维表。
  • 元组 (Tuple): 表中的一行记录。
  • 属性 (Attribute): 表中的一列，有属性名（列名）。
  • 码 (Key): 唯一确定一个元组的属性或一组属性。
  • 域 (Domain): 属性的取值范围，比如“年龄”的域是0-150之间的整数。
  • 分量: 元组中的一个具体属性值（一个单元格里的数据）。
  • 关系模式: 对关系的结构描述，比如 `学生(学号,姓名,性别,出生日期,主修专业)`，这说明了“学生”表有哪些列。

规范化要求: 关系模型的表格必须是“平坦的”，即每个单元格（分量）里只能是不可再分的数据项，不能再包含子表格或其他复杂结构。这保证了数据的一致性和简洁性。

码: 主码和外码的描述 ⭐ (3次真题出现)

  • 主码 (Primary Key): 能够唯一标识表格中每一行记录的属性或属性组。它的值必须是唯一的，且不能为空。
    • 就像每个人的身份证号，是唯一的，不会重复，也不能没有。在学生表里，“学号”就是典型的主码。
  • 外码 (Foreign Key): 一个表格中的一个属性或属性组，它的值参照（匹配）另一个表格的主码的值。外码是连接不同表格的关键。
    • 如果有一个“选课表”，里面有“学号”和“课程号”，这个“学号”在选课表里就是外码，它指向了“学生表”里的那个学生的学号（主码），通过它就能知道是哪个学生选了课。

关系模型的优缺点：

优点 缺点
建立在严格的数学概念基础上，结构非常清晰和严谨。 查询效率在某些复杂情况下可能不如老式数据库（因为用户看不到底层存储细节，DBMS需要额外优化）。
概念单一，所有数据和关系都用“表”来表示，容易理解和使用。 为了保证性能，数据库管理系统内部需要进行复杂的查询优化，这增加了DBMS自身的开发难度。
存取路径对用户透明（用户不需要知道数据具体存在哪里），数据独立性高，安全保密性好。
简化了程序员的开发工作，只需要告诉DBMS“要什么数据”，而不需要关心“怎么取数据”。

1.3 数据库系统的三级模式结构

重要程度:

1.3.1 数据库系统中模式的概念 ⭐ (必考核心, 5次真题出现)

型 (Type) 和值 (Value)

  • 型： 对某一类数据的结构和特征的描述。
    • 就像你定义一个变量是“整数类型”，这个“整数”就是型。
  • 值： 型的一个具体内容或赋值。
    • 当你把那个“整数类型”的变量赋值为“10”，这个“10”就是值。

模式 (Schema) 和实例 (Instance)

  • 模式： 数据库中全体数据的逻辑结构和特征的描述，是所有用户的公共数据视图，只描述结构，不涉及具体内容。它是唯一的，相对稳定。
    • 就像一本图书馆的“总设计图”，它规定了所有书籍如何分类、书架如何编号等规则，但图上不会画出每一本书的封面和内容。这个总设计图一旦确定，就不会轻易改变。
  • 实例： 模式的一个具体数据集合，反映数据库在某一特定时刻的状态。实例会随着数据库中数据的更新而变动。
    • 就像图书馆在某个特定时间点，所有书架上摆放的每一本书的实际内容。读者借还书、新书入库，图书馆的“实例”就在不断变化。

1.3.2 数据库系统的三级模式结构 ⭐ (必考核心)

数据库系统通过三个抽象级别来管理数据，分别对应用户、逻辑和物理视图：

  • 模式 (Schema) / 逻辑模式:

    是数据库的中心与关键，描述了数据库中所有数据的完整逻辑结构和特征，是所有用户共享的通用视图。一个数据库只有一个模式。

  • 外模式 (External Schema) / 子模式 / 用户模式:

    描述了数据库用户（或应用程序）能看到和使用的局部数据结构。不同用户或应用程序可能看到数据库的不同部分，或者以不同的方式看到同一部分。一个数据库可以有多个外模式，外模式也是保证数据库安全性的重要手段。

    • 就像图书馆给不同读者发放的“定制化目录”。学生读者只能看到普通图书的目录，而教授可能能看到更多专业资料的目录。你只能看到自己权限范围内的“一部分数据视图”。
  • 内模式 (Internal Schema) / 物理模式 / 存储模式:

    描述了数据在数据库内部的物理存储结构和组织方式。这包括数据记录如何存放（如堆放、按顺序放）、索引如何组织（如B+树、哈希表）、数据是否被压缩或加密等最底层的细节。

    • 就像图书馆的“仓库管理系统”，它精确记录了每本书在哪个仓库的哪个货架的第几层，甚至连书是平放还是竖放，有没有被塑料薄膜打包都记录得清清楚楚。这些细节是普通读者看不到的。

1.3.3 数据库的两级映像与数据独立性 ⭐ (必考核心, 7次真题出现)

两级映像是DBMS内部实现三个抽象层次之间转换的关键机制，它们是实现数据独立性的基石。

1. 外模式/模式映像

定义了外模式与模式之间的对应关系。

逻辑独立性： 当数据库的模式（全局逻辑结构）发生改变时（例如，给某个表格添加一列），数据库管理员（DBA）会修改外模式/模式映象，使得外模式保持不变，应用程序因此无需修改。这保证了应用程序对数据库逻辑结构变化的免疫性。

  • 假设图书馆“总目录”（模式）增加了“书籍评分”这一项。但你用的“学生阅览区目录”（外模式）不需要显示评分。DBMS会通过“外模式/模式映像”这个“翻译层”来处理，你的应用程序无需改动就能继续正常工作。

2. 模式/内模式映像

定义了数据全局逻辑结构与存储结构之间的对应关系。

物理独立性： 当数据库的存储结构（内模式）发生改变时（例如，为了提高性能，数据库文件从硬盘A移动到硬盘B，或者数据存储方式从顺序改为散列），DBA会修改模式/内模式映象，使得模式保持不变，应用程序因此不必改变。这保证了应用程序对数据库物理存储变化的免疫性。

  • 图书馆为了提高查找速度，把一些经常被借阅的书从一个仓库搬到了另一个更快的仓库，并且调整了它们的实际摆放方式。你从“总目录”（模式）上看，这些书的信息和分类都没变。DBMS通过“模式/内模式映像”这个“翻译层”，自动帮你处理了底层存储的变化，你和你的应用程序完全感觉不到。

核心价值： 两级映像使得数据的定义和描述可以从应用程序中分离出去，极大简化了应用程序的编制，并大大降低了应用程序的开发和维护成本。

1.4 数据库系统的组成

重要程度:

数据库系统的组成 ⭐ (必考核心, 4次真题出现)

一个完整的数据库系统主要由以下几部分构成：

1. 硬件平台

是数据库管理系统运行的基础，包括计算机硬件（如CPU、内存）和存储设备（如硬盘）。硬件性能的提升直接影响数据库处理数据的能力。

  • 就像图书馆的“基础设施”，包括图书馆大楼、所有的书架、电脑设备和服务器等。

2. 软件平台

  • 操作系统: 提供基本的计算环境，DBMS运行在其之上。
  • 数据库管理系统 (DBMS): 是数据库系统的核心软件，负责所有数据管理功能。
  • 高级语言及编译系统: 用于编写与数据库交互的应用程序，比如Java、Python等。
  • 应用开发工具: 辅助开发者更高效地构建数据库应用。
  • 数据库应用系统: 为特定业务需求（如学生管理、电商交易）开发的、最终用户直接使用的软件。
  • 就像图书馆里的“软件系统”，包括图书管理软件、读者借阅系统、以及运行这些系统的电脑操作系统等。

3. 人员

  • 数据库管理员 (DBA): 是数据库系统的总负责人，负责数据库的整体规划、设计、安装、配置、日常运行维护、性能调优、安全管理、权限控制、备份与恢复等。
    • 就像图书馆的“总馆长”，他不仅要懂图书馆的各种管理规定，还要确保所有书籍安全、读者能顺利借阅、图书馆能高效运转。
  • 系统分析员和数据库设计人员: 负责理解用户需求，进行系统总体设计，并设计数据库的各级模式（概念模式、逻辑模式、物理模式）。
    • 就像图书馆的“设计师和规划师”，他们根据读者和馆方的需求，设计图书馆的布局、书籍的分类规则等。
  • 应用程序员: 根据数据库设计，编写实现具体业务逻辑的应用程序，并通过DBMS与数据库进行交互。
    • 就像负责开发图书馆“自助借还系统”或“在线查询系统”的软件工程师。
  • 最终用户: 通过应用程序来使用数据库，完成他们的日常业务活动，如查询信息、提交订单等。
    • 就像来图书馆借书、还书、在电脑上查询书目的普通读者。

非考点内容 (了解)

重要程度:

数据模型的发展和新型数据模型了解内容

数据模型从层次模型、网状模型发展到关系模型，并在此基础上涌现出面向对象模型和如键值对模型、文档模型、图模型、时序模型等新型数据模型。这些新型模型旨在应对大数据和NoSQL场景的需求，但在完整性约束等方面仍有待深入研究和发展。

数据库系统的体系结构了解内容

数据库系统根据其组织方式可以分为集中式数据库系统、客户-服务器数据库系统、并行数据库系统、分布式数据库系统和云数据库系统等。每种体系结构都有其特定的优势和应用场景，以适应不同规模和需求的数据的处理环境。
