第五章--数据库完整性

本章重点梳理数据库完整性的核心概念、三种主要完整性（实体、参照、用户定义）及其SQL实现与违约处理，并简要提及触发器和完整性命名子句。

5.1 数据库完整性概述 必考

  • 定义

    数据库完整性是指数据的正确性和相容性。正确性指数据符合现实世界语义，反映实际状况；相容性指数据库同一对象在不同表中数据保持一致。

  • 与安全性的区别

    完整性是防止不合语义或不正确的数据进入数据库；安全性是保护数据库防止恶意的破坏和非法存取。

    方面 完整性 安全性
    目的 防止错误数据进入数据库 防止未授权访问和恶意破坏
    关注点 数据正确性和一致性 数据访问权限控制
    示例 年龄不能为负数 用户访问权限管理
  • RDBMS维护完整性的方法
    • 提供定义完整性约束的机制：通过SQL数据定义语言（DDL）语句实现。
    • 提供检查完整性约束的方法：通常在INSERT、UPDATE、DELETE语句执行后检查，也可在事务提交时检查。
    • 提供完整性的违约处理方法：包括拒绝执行（默认）、级联操作（CASCADE）、设置为空值（SET NULL）。

5.2 实体完整性 必考

5.2.1 定义实体完整性

  • 通过PRIMARY KEY定义主码

    关系模型要求主码值唯一且非空。主码是唯一标识元组的属性或属性组。

    主键约束 说明
    PRIMARY KEY 标识唯一标识表中每一行的列或列组合
    NOT NULL 主键列自动隐含，不能包含空值
    UNIQUE 主键值在整个表中必须唯一
    SQL Code: Student Table Primary Key Definition 
    CREATE TABLE Student (
    Sno CHAR(8) PRIMARY KEY, -- 列级定义主码，学号
    Sname CHAR(20) UNIQUE,
    Ssex CHAR(6),
    Sbirthdate Date,
    Smajor VARCHAR(40)
);

-- 或者在表级定义主码
CREATE TABLE Student2 (
    Sno CHAR(8),
    Sname CHAR(20) UNIQUE,
    Ssex CHAR(6),
    Sbirthdate Date,
    Smajor VARCHAR(40),
    PRIMARY KEY (Sno) -- 表级定义主码
);

-- 复合主码必须在表级定义
CREATE TABLE SC (
    Sno CHAR(8),
    Cno CHAR(5),
    Grade SMALLINT,
    PRIMARY KEY (Sno,Cno) -- (Sno,Cno)作为复合主码
);

5.2.2 实体完整性检查和违约处理

  • 检查时机：插入新元组或更新主码列时。
  • 检查内容：
    • 主码值是否唯一。
    • 主码的各个属性是否为空（只要有一个为空就拒绝）。
  • 违约处理：如果不满足，则拒绝插入或修改操作。RDBMS通常通过主码上的索引（如B+树索引）来高效检查唯一性，避免全表扫描。

5.3 参照完整性 必考

5.3.1 定义参照完整性

  • 通过FOREIGN KEY和REFERENCES定义

    定义外码（FOREIGN KEY）并指明它参照哪个表的主码（REFERENCES）。外码的值要么为空（如果允许），要么必须等于被参照表中某个主码的值。

    外键约束 说明
    FOREIGN KEY 建立表之间的关联关系
    REFERENCES 指定被参照的表和列
    ON DELETE 定义当被参照行被删除时的操作
    ON UPDATE 定义当被参照行被更新时的操作
    SQL Code: Foreign Key Definition 
    CREATE TABLE SC_FK (
    Sno CHAR(8),
    Cno CHAR(5),
    Grade SMALLINT,
    PRIMARY KEY (Sno, Cno),
    FOREIGN KEY (Sno) REFERENCES Student(Sno), -- Sno是外码，参照Student表
    FOREIGN KEY (Cno) REFERENCES Course(Cno) -- Cno是外码，参照Course表
);

5.3.2 参照完整性检查和违约处理

  • 可能破坏参照完整性的操作：
    • 参照表（子表）操作：

      插入新元组或修改外码值时，如果外码值在被参照表（父表）中找不到对应的主码值，则破坏完整性。

    • 被参照表（父表）操作：

      删除元组或修改主码值时，如果被删除/修改的主码值在参照表（子表）中仍有引用，则破坏完整性。

  • 违约处理策略：
    • 拒绝执行 (NO ACTION / RESTRICT)：默认策略，不允许破坏完整性的操作执行。
    • 级联操作 (CASCADE)：

      当删除或修改被参照表的一个元组时，级联删除或修改参照表中所有相关联的元组。

      示例：删除学生记录时，自动删除该学生的所有选课记录
    • 设置为空值 (SET NULL)：

      当删除或修改被参照表的一个元组时，将参照表中所有相关联元组的外码属性设置为NULL。注意：外码列必须允许为空值。

      示例：删除课程记录时，将该课程的所有选课记录的课程号设为NULL
    策略 ON DELETE ON UPDATE 适用场景
    NO ACTION 拒绝删除 拒绝更新 默认策略，确保强关联
    CASCADE 级联删除 级联更新 强关联，需要同步删除/更新
    SET NULL 设为NULL 设为NULL 弱关联，允许部分数据缺失

    在CREATE TABLE语句中可以显式指定违约处理方式：

    SQL Code: Foreign Key with Actions 
    CREATE TABLE SC_Actions (
    Sno CHAR(8),
    Cno CHAR(5),
    Grade SMALLINT,
    PRIMARY KEY(Sno,Cno),
    FOREIGN KEY (Sno) REFERENCES Student(Sno)
        ON DELETE CASCADE, -- 删除Student元组时，级联删除SC中对应元组
        ON UPDATE CASCADE, -- 更新Student的Sno时，级联更新SC中对应Sno
    FOREIGN KEY (Cno) REFERENCES Course(Cno)
        ON DELETE NO ACTION, -- 删除Course元组时，拒绝删除（默认行为）
        ON UPDATE CASCADE
);

5.4 用户定义的完整性 必考

用户定义的完整性是针对具体应用语义要求的完整性约束，由RDBMS提供机制进行定义和检验。

5.4.1 属性上的约束

  • 列值非空 (NOT NULL)

    确保指定列的值不能为空。

    SQL Code: NOT NULL Constraint 
    CREATE TABLE SC_NotNull (
    Sno CHAR(8) NOT NULL,
    Cno CHAR(5) NOT NULL,
    Grade SMALLINT NOT NULL,
    PRIMARY KEY (Sno, Cno) -- 主码已隐含NOT NULL，此处可省略
);
  • 列值唯一 (UNIQUE)

    确保指定列的所有值都是唯一的，但允许有NULL值（如果未定义NOT NULL）。

    SQL Code: UNIQUE Constraint 
    CREATE TABLE School (
    SHno CHAR(8) PRIMARY KEY,
    SHname VARCHAR(40) UNIQUE, -- 学院名称唯一
    SHfounddate Date
);
  • 检查列值是否满足条件表达式 (CHECK)

    通过CHECK短语定义列值必须满足的条件，例如取值范围、枚举值等。

    约束类型 关键字 用途
    非空约束 NOT NULL 确保列值不为空
    唯一约束 UNIQUE 确保列值唯一
    检查约束 CHECK 定义列值的条件表达式
    SQL Code: CHECK Constraint 
    CREATE TABLE Student_Check (
    Sno CHAR(8) PRIMARY KEY,
    Sname CHAR(20) NOT NULL,
    Ssex CHAR(6) CHECK (Ssex IN ('男', '女')), -- 性别只能是'男'或'女'
    Sbirthdate Date,
    Smajor VARCHAR(40)
);

CREATE TABLE SC_Check (
    Sno CHAR(8),
    Cno CHAR(5),
    Grade SMALLINT CHECK (Grade>=0 AND Grade <=100), -- 成绩在0到100之间
    Semester CHAR(5),
    Teachingclass CHAR(8),
    PRIMARY KEY (Sno, Cno),
    FOREIGN KEY (Sno) REFERENCES Student(Sno),
    FOREIGN KEY (Cno) REFERENCES Course(Cno)
);
  • 检查和违约处理：在插入或修改属性值时进行检查，不满足则拒绝执行。

5.4.2 元组上的约束

  • 通过CHECK短语定义元组级限制

    可以设置元组内不同属性之间的相互约束关系，比属性级约束更灵活。

    示例：确保出生日期小于入职日期
    SQL Code: Tuple-level CHECK Constraint 
    CREATE TABLE Student_TupleCheck (
    Sno CHAR(8),
    Sname CHAR(20) NOT NULL,
    Ssex CHAR(6),
    Sbirthdate Date,
    Smajor VARCHAR(40),
    PRIMARY KEY (Sno),
    CHECK (Ssex='女' OR Sname NOT LIKE 'Ms.%') -- 如果是男性，名字不能以'Ms.'开头
);
  • 检查和违约处理：在插入元组或修改属性值时进行检查，不满足则拒绝执行。

5.5 完整性约束命名子句 重要

  • 格式：CONSTRAINT <完整性约束名> <完整性约束>

    允许为各种完整性约束（如NOT NULL, UNIQUE, PRIMARY KEY, FOREIGN KEY, CHECK）指定一个名称，方便后续的修改或删除操作。

    命名约束语法模板：
    CONSTRAINT 约束名 约束类型 (约束条件)

    -- 约束名：自定义的约束名称，便于后续修改或删除

    -- 约束类型：NOT NULL、UNIQUE、PRIMARY KEY、FOREIGN KEY、CHECK等

    修改约束语法模板：
    ALTER TABLE 表名 DROP CONSTRAINT 约束名;
    ALTER TABLE 表名 ADD CONSTRAINT 约束名 约束类型 (约束条件);
    SQL Code: Named Constraints 
    CREATE TABLE Student_NamedConstraints (
    Sno CHAR(8)
        CONSTRAINT C1 CHECK (Sno BETWEEN '10000000' AND '29999999'), -- 学号范围约束，命名C1
    Sname CHAR(20)
        CONSTRAINT C2 NOT NULL, -- 姓名非空约束，命名C2
    Sbirthdate Date
        CONSTRAINT C3 CHECK (Sbirthdate > '1980-1-1'), -- 出生日期约束，命名C3
    Ssex CHAR(6)
        CONSTRAINT C4 CHECK (Ssex IN ('男', '女')), -- 性别约束，命名C4
    Smajor VARCHAR(40),
    CONSTRAINT StudentKey PRIMARY KEY(Sno) -- 主码约束，命名StudentKey
);

-- 修改完整性限制示例：删除对出生日期的限制
ALTER TABLE Student_NamedConstraints DROP CONSTRAINT C3;

-- 修改并重新添加约束示例
ALTER TABLE Student_NamedConstraints DROP CONSTRAINT C1;
ALTER TABLE Student_NamedConstraints ADD CONSTRAINT C1 CHECK (Sno BETWEEN '900000' AND '999999');

5.7 触发器 了解

  • 概念： 触发器是用户定义在关系表上的一类事件驱动的特殊过程。

    当数据库中发生特定事件（如增、删、改数据）时，触发器会自动执行预定义的动作。它能实施更复杂、更精细的数据完整性检查和操作。

    触发器语法模板：
    CREATE TRIGGER 触发器名
    {BEFORE | AFTER} 触发事件 ON 表名
    REFERENCING {NEW | OLD} AS 变量
    FOR EACH {ROW | STATEMENT}
    [WHEN 触发条件]
    触发动作体;
  • 定义格式（ECA规则）：

    CREATE TRIGGER <触发器名> {BEFORE | AFTER} <触发事件> ON <表名> REFERENCING NEW|OLD AS<变量> FOR EACH {ROW | STATEMENT} [WHEN <触发条件>]<触发动作体>

    • 触发时机 (BEFORE | AFTER)：在触发事件前或后执行。
    • 触发事件 (INSERT, DELETE, UPDATE)：导致触发器激活的操作。
    • 触发粒度 (FOR EACH ROW | STATEMENT)：

      行级触发器：操作影响多少行就触发多少次，可使用NEW和OLD引用新旧值。
      语句级触发器：无论影响多少行，整个SQL语句执行后只触发一次。

    • 触发条件 (WHEN)：满足此条件才执行触发动作。
    • 触发动作体：触发器实际执行的SQL语句或过程。
    SQL Code: Trigger Example 
    -- 创建审计日志表
CREATE TABLE AuditLog (
    LogID INT PRIMARY KEY,
    Action VARCHAR(10),
    TableName VARCHAR(20),
    UserID VARCHAR(20),
    Timestamp TIMESTAMP
);

-- 创建行级触发器
CREATE TRIGGER Audit_Student_Update
AFTER UPDATE ON Student
REFERENCING OLD AS old_row
FOR EACH ROW
BEGIN
    INSERT INTO AuditLog (Action, TableName, UserID, Timestamp)
    VALUES ('UPDATE', 'Student', USER, CURRENT_TIMESTAMP);
END;
  • 执行顺序：
    • 1. 执行该表上的BEFORE触发器。
    • 2. 激活触发器的SQL语句（如INSERT/UPDATE/DELETE）。
    • 3. 执行该表上的AFTER触发器。
  • 删除触发器： DROP TRIGGER <触发器名> ON <表名>;
