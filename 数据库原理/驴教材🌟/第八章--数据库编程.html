8.1.1 SQL语言表达能力的限制 必考

尽管SQL功能强大，但在某些复杂应用场景下仍存在表达能力的限制，主要体现在以下几个方面：

  • 无法表达递归等复杂操作：

    例如，查询课程的所有先修课信息（直接和间接先修课）。传统SQL难以实现这类多层递归查询。

8.1.2 扩展SQL的功能 重要

为了弥补传统SQL的局限性，数据库系统通过以下方式扩展其功能：

  1. 引入新的SQL子句： 例如，WITH RECURSIVE子句用于支持递归查询，以及面向联机分析处理（OLAP）、空间数据管理、文档数据管理的SQL扩展。
  2. 引入新的内置函数： 增加数学、聚合、字符串、日期时间、格式化、控制流、加密、系统信息等函数，以处理更复杂的数据操作。
  3. 引入PL/SQL与存储过程/存储函数： 允许用户自定义程序逻辑，实现业务逻辑复杂的应用系统。

8.1.3 通过高级语言实现复杂应用 了解

除了SQL本身的扩展，还可以通过将数据库操作与高级语言结合来实现复杂应用：

  • 通过动态链接库调用方式： 数据库管理系统的功能被包装成子程序，应用程序通过动态链接库调用来获得数据管理功能。
  • 基于嵌入式SQL方式： 将SQL语句嵌入到高级语言中混合编程，SQL负责数据操纵，高级语言负责控制逻辑流程。
  • 基于ODBC/JDBC的中间件方式： 建立连接不同数据库的一组规范。无论使用何种数据库，都采用同样一组API来访问数据库。

8.2 过程化SQL (Procedural SQL) 必考

8.2.1 过程化SQL的块结构 重要

过程化SQL是SQL的扩展，增加了过程化语句功能。其基本结构是“块”，块之间可以互相嵌套，每个块完成一个逻辑操作。

过程化SQL块的基本结构：

  1. 定义部分 (`DECLARE`)：

    用于定义变量、常量、游标、异常等。这些定义仅在该基本块中使用，当基本块执行结束时，定义就不再存在。

  2. 执行部分 (`BEGIN ... END`)：

    包含SQL语句、过程化SQL的流程控制语句，以及可选的异常处理部分 (`EXCEPTION`)。

SQL Code Example: Basic Block Structure
DECLARE     -- 变量、常量、游标、异常等的定义 BEGIN     -- SQL语句和过程化SQL的流程控制语句 EXCEPTION     -- 异常处理部分 END;

说明： 这是一个PL/SQL（或类似过程化SQL）的基本块结构范例。

8.2.2 变量和常量的定义 重要

  • 变量定义：

    变量名 数据类型 [[NOT NULL] := 初值表达式] 或 变量名 数据类型 [[NOT NULL] 初值表达式]

  • 常量定义：

    常量名 数据类型 CONSTANT := 常量表达式

    常量必须被赋予一个值，且该值在其作用域内不能改变。试图修改它将引发异常。

  • 赋值语句：

    变量名称 := 表达式

8.2.3 流程控制 重要

过程化SQL提供以下流程控制功能：

  1. 条件控制语句：
    • IF-THEN
    • IF-THEN-ELSE
    • 嵌套的IF语句
  2. 循环控制语句：
    • 简单的循环语句 LOOP ... END LOOP (通常配合 EXIT/BREAK/LEAVE 提前结束)
    • WHILE-LOOP：每次执行循环体前求值条件，为真则执行。
    • FOR-LOOP：通过指定范围进行迭代。
  3. 错误处理 (`EXCEPTION`)：

    当执行时出现异常，程序将在异常语句处停止，并执行异常处理语句。

控制结构 语法模板 说明

8.2.4 游标 (Cursor) 的定义与使用 必考

当SELECT语句返回多条记录时，需要使用游标对结果集进行逐行处理。一个游标与一个SQL语句相关联。

游标的用户接口步骤：

  1. 声明游标 (`DECLARE CURSOR`)：

    DECLARE 游标名 [(参数列表)] CURSOR FOR SELECT语句;

    此为说明性语句，DBMS此时不执行SELECT语句。

  2. 打开游标 (`OPEN CURSOR`)：

    OPEN 游标名[(参数列表)];

    执行SELECT语句，将查询结果取到缓冲区，游标处于活动状态，指针指向第一条记录。

  3. 使用游标 (`FETCH`)：

    FETCH 游标名 INTO 变量1[, 变量2,...];

    将游标指针向前推进一条记录，同时将当前记录取出至变量供处理。需循环执行FETCH语句。

  4. 关闭游标 (`CLOSE CURSOR`)：

    CLOSE 游标名;

    游标被关闭后不再与原查询结果集关联，但可以再次打开与新的查询结果关联。

游标属性 描述
%FOUND 如果FETCH操作成功获取一行数据，则返回TRUE
%NOTFOUND 如果FETCH操作未能获取数据，则返回TRUE
%ISOPEN 如果游标已经打开，则返回TRUE
%ROWCOUNT 返回到目前为止通过游标提取的行数

例8.4：根据给定学号20180001，使用游标输出该学生的所有选课记录。

SQL Code Example: Cursor Usage
DECLARE     CnoOfStudent CHAR(10);     GradeOfStudent INT;     mycursor CURSOR FOR         SELECT Cno, Grade FROM SC         WHERE Sno = '20180001'; BEGIN     OPEN mycursor; /* 打开游标 */     LOOP /* 循环遍历游标 */         FETCH mycursor INTO CnoOfStudent, GradeOfStudent; /* 检索游标 */         EXIT WHEN mycursor%NOTFOUND;         RAISE NOTICE 'Sno:20180001, Cno:%, Grade:%', CnoOfStudent, GradeOfStudent;     END LOOP;     CLOSE mycursor; /* 关闭游标 */ END;
模拟运行结果

Sno:20180001, Cno:81001, Grade:85
Sno:20180001, Cno:81002, Grade:96
Sno:20180001, Cno:81003, Grade:87

8.2.5 存储过程 (Stored Procedure) 必考

存储过程是命名并保存在数据库中的过程化SQL程序，可供其他程序调用。

存储过程的用户接口：

  1. 创建存储过程 (`CREATE PROCEDURE`)：

    CREATE [OR REPLACE] PROCEDURE 过程名 (参数列表) AS <过程化SQL块>;

    参数模式有IN（输入）、OUT（输出）、INOUT（输入输出），默认IN。

  2. 执行存储过程 (`CALL/PERFORM`)：

    CALL/PERFORM [PROCEDURE] 过程名 ([参数1, 参数2,...]);

  3. 修改存储过程 (`ALTER PROCEDURE`)：

    用于重命名或重新编译。

  4. 删除存储过程 (`DROP PROCEDURE`)：

    DROP PROCEDURE 过程名;

存储过程的优点：

  • 运行效率高（预编译）。
  • 降低了客户机和服务器之间的通信量。
  • 方便实施企业规则（业务逻辑集中管理）。

例8.5：给定学生学号，计算学生的平均学分绩点GPA。

SQL Code Example: compGPA Procedure
CREATE OR REPLACE PROCEDURE compGPA(     IN inSno CHAR(10), /* 输入参数：学生学号inSno */     OUT outGPA FLOAT /* 输出参数：平均学分绩outGPA */ ) AS DECLARE     courseGPA INT; /* 声明变量courseGPA，临时存储课程学分绩 */     totalGPA INT; /* 声明变量totalGPA，临时存储总学分绩 */     totalCredit INT; /* 声明变量totalCredit，临时存储总学分 */     grade INT; /* 声明变量grade，临时存储学生成绩 */     credit INT; /* 声明变量credit，临时存储课程学分 */     mycursor CURSOR FOR /* 声明游标mycursor */         SELECT C.Ccredit, SC.Grade FROM SC, Course AS C         WHERE SC.Sno = inSno AND SC.Cno = C.Cno; BEGIN     totalGPA := 0;     totalCredit := 0;     OPEN mycursor; /* 打开游标mycursor */     LOOP /* 循环遍历游标 */         FETCH mycursor INTO credit, grade; /* 检索游标 */         EXIT WHEN mycursor%NOTFOUND;         IF grade BETWEEN 90 AND 100 THEN             courseGPA := 4.0;         ELSIF grade BETWEEN 80 AND 89 THEN             courseGPA := 3.0;         ELSIF grade BETWEEN 70 AND 79 THEN -- Corrected from 72 for common GPA scale             courseGPA := 2.0;         ELSIF grade BETWEEN 60 AND 69 THEN             courseGPA := 1.0;         ELSE             courseGPA := 0;         END IF; /* 参照绩点对照表，根据成绩找出某门课程对应的学分绩点 */         totalGPA := totalGPA + courseGPA * credit;         totalCredit := totalCredit + credit;     END LOOP;     CLOSE mycursor; /* 关闭游标mycursor */     IF totalCredit > 0 THEN         outGPA := 1.0 * totalGPA / totalCredit;     ELSE         outGPA := 0.0; -- Handle division by zero if no courses found     END IF; END;
模拟运行结果 (调用 compGPA('20180001', outGPA) )

GPA for student 20180001: 3.33 (assuming 81001, 81002, 81003 all have 4 credits)
计算逻辑: (85分对应3绩点*4学分 + 96分对应4绩点*4学分 + 87分对应3绩点*4学分) / (4+4+4) = (12+16+12)/12 = 40/12 ≈ 3.33

8.2.6 存储函数 (Stored Function) 重要

存储函数与存储过程类似，也是持久性存储模块，但主要区别在于函数**必须指定返回类型**并返回一个值。

存储函数的定义语句格式：

CREATE [OR REPLACE] FUNCTION 函数名([参数列表]) RETURNS <类型> AS <过程化SQL块>;

函数的执行语句格式：

CALL/SELECT 函数名 ([参数1,参数2,...]);

类似存储过程，函数也可以被修改和删除。

特性 存储过程 (Procedure) 存储函数 (Function)
返回值 无返回值或通过OUT参数返回 必须返回一个值
调用方式 CALL procedure_name() SELECT function_name()
SQL语句中调用 不能直接在SELECT中使用 可以直接在SELECT中使用
事务控制 可以包含事务控制语句 通常不包含事务控制
主要用途 执行业务逻辑，数据处理 计算并返回结果

8.3 JDBC编程 (Java Database Connectivity) 必考

8.3.1 JDBC工作原理概述 重要

背景：不同数据库管理系统（DBMS）间的应用程序不兼容，导致数据共享和访问困难。

JDBC定义：是Java语言的软件开发工具包（JDK）中用于数据库访问的组成部分，提供了一组访问数据库的应用程序编程接口（API）。

JDBC的约束力：

  • 规范应用开发，使其通过JDBC接口而不是特定RDBMS接口进行开发。
  • 规范RDBMS应用接口，要求RDBMS必须实现所有JDBC接口。

JDBC应用系统的体系结构：

  1. 用户应用程序：使用JDBC API与数据库交互。
  2. JDBC驱动程序管理器 (`DriverManager`)：负责管理和加载各种JDBC驱动程序。
  3. 数据源：具体的数据库（如Kingbase、Oracle、MySQL、SQL Server等）。
  4. 数据库驱动程序：由各数据库厂商提供，实现JDBC接口，负责将JDBC调用转换为特定数据库协议。

JDBC体系结构示意图

JDBC简化架构：

应用程序 (Application) <--- JDBC API ---> JDBC 驱动程序管理器 (JDBC Driver Manager) <--- JDBC 驱动程序 (JDBC Driver) ---> 数据库 (Database)

JDBC详细架构：

  • 应用程序层：调用JDBC API来执行数据库操作。
  • JDBC API层：由`java.sql`包提供，提供连接数据库、执行SQL、处理结果等接口。
  • JDBC驱动程序管理器层：`DriverManager`类，负责加载JDBC驱动，并根据URL选择合适的驱动建立连接。
  • JDBC驱动程序层：各数据库厂商（如Oracle, MySQL, SQL Server）提供的具体实现，将JDBC调用转换为数据库原生协议。
  • 数据库层：实际存储数据的DBMS。

8.3.3 使用JDBC操纵数据库的工作流程 必考

使用JDBC连接和操作数据库通常遵循以下步骤：

  1. 注册JDBC驱动程序： 加载特定数据库的JDBC驱动程序类。
  2. 建立数据库连接： 通过DriverManager.getConnection()方法获取Connection对象。
  3. 创建Statement对象： 通过Connection对象创建Statement、PreparedStatement或CallableStatement对象。
  4. 执行SQL语句： 使用Statement对象执行SQL语句（查询、更新、插入、删除）。
  5. 处理查询结果： 对于查询操作，通过ResultSet对象迭代处理结果集。
  6. 关闭连接和资源： 按照ResultSet、Statement、Connection的顺序依次关闭资源。
步骤 关键代码 说明
1. 加载驱动 Class.forName("com.mysql.cj.jdbc.Driver"); 加载数据库驱动类
2. 建立连接 Connection conn = DriverManager.getConnection(url, user, password); 创建数据库连接
3. 创建语句 Statement stmt = conn.createStatement();
或 PreparedStatement pstmt = conn.prepareStatement(sql);		 创建SQL执行对象
4. 执行SQL ResultSet rs = stmt.executeQuery(sql);
int rows = stmt.executeUpdate(sql);		 执行查询或更新操作
5. 处理结果 while(rs.next()) {
  String name = rs.getString("name");
}		 遍历结果集获取数据
6. 关闭资源 rs.close();
stmt.close();
conn.close();		 释放数据库资源

JDBC查询示例 
import java.sql.*;

public class JdbcExample {
    public static void main(String[] args) {
        // 数据库连接信息
        String url = "jdbc:mysql://localhost:3306/school_db";
        String user = "root";
        String password = "password";
        
        // 声明JDBC对象
        Connection conn = null;
        Statement stmt = null;
        ResultSet rs = null;
        
        try {
            // 1. 注册驱动 (JDBC 4.0+ 自动加载，可省略)
            Class.forName("com.mysql.cj.jdbc.Driver");
            
            // 2. 获取数据库连接
            conn = DriverManager.getConnection(url, user, password);
            
            // 3. 创建Statement对象
            stmt = conn.createStatement();
            
            // 4. 执行SQL查询
            String sql = "SELECT sno, sname, ssex FROM student WHERE smajor = '计算机科学与技术'";
            rs = stmt.executeQuery(sql);
            
            // 5. 处理结果集
            while(rs.next()) {
                String sno = rs.getString("sno");
                String sname = rs.getString("sname");
                String ssex = rs.getString("ssex");
                
                System.out.printf("学号: %s, 姓名: %s, 性别: %s%n", sno, sname, ssex);
            }
        } catch (ClassNotFoundException | SQLException e) {
            e.printStackTrace();
        } finally {
            // 6. 关闭资源
            try {
                if(rs != null) rs.close();
                if(stmt != null) stmt.close();
                if(conn != null) conn.close();
            } catch (SQLException e) {
                e.printStackTrace();
            }
        }
    }
}

8.4 基于MVC框架的数据库应用开发 了解

MVC框架简介

MVC (Model-View-Controller) 是一种软件架构模式，用于将应用程序的业务逻辑、数据和用户界面分离，以提高代码的可维护性、可扩展性以及可重用性。

  • Model (模型)： 负责管理应用程序的数据、业务逻辑和规则。它独立于用户界面，处理数据的存储、检索、更新。在数据库应用中，模型通常与数据库交互。
  • View (视图)： 负责数据的展示，即用户界面。它不包含任何业务逻辑，只负责接收模型的数据并显示给用户。
  • Controller (控制器)： 负责接收用户输入，并根据输入调用模型进行数据处理，然后选择合适的视图来显示结果。它充当模型和视图之间的协调者。

优点： 职责分离、提高开发效率、易于测试、更好的可维护性。

MVC架构流程：

  1. 用户操作：用户通过视图（View）与应用程序交互。
  2. 控制器接收：控制器（Controller）接收并处理来自视图的用户输入。
  3. 调用模型：控制器根据输入，调用相应的模型（Model）进行数据处理或业务逻辑操作。
  4. 模型处理：模型执行操作，可能涉及数据库访问、数据计算等。处理完成后，模型通知相关视图数据已更新。
  5. 视图更新：视图从模型获取更新后的数据，并重新渲染展示给用户。

这种分离使得各部分可以独立开发和测试，提高了系统的健壮性和可维护性。

在数据库应用中的体现

  • Model层： 负责与数据库的交互，包括执行SQL语句、处理事务、管理数据持久化等。通常包含DAO (Data Access Object) 或 Repository 层。
  • View层： 负责展示从Model层获取的数据，通常是HTML、JSP、Vue、React等前端页面。
  • Controller层： 接收HTTP请求，调用Model层的业务方法，然后将处理结果传递给View层进行展示。

采用MVC框架可以更好地组织代码结构，使得数据库应用更加模块化和易于管理。
