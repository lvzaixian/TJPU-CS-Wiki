第四章--数据库安全性

保护您的数据城堡：数据库安全的秘密武器

4.1 数据库安全性概述 必考

数据库安全性：啥是安全？

数据库的安全性，指的是保护数据库，防止未经授权的访问、恶意修改或破坏。

就像你家的金库，要保证没人能随便进去，进去了也不能乱动，更不能破坏。

数据库为啥不安全？

  • 非授权用户恶意存取和破坏。

    比如，黑客通过各种手段盗取你的账号密码，然后假冒你来偷数据或搞破坏。

  • 敏感数据泄露。

    公司的核心机密、客户的隐私信息等，被人偷偷拿走了。

  • 安全环境脆弱。

    数据库跑在电脑和网络上，如果电脑系统有漏洞，或者网络不安全，数据库本身再安全也可能受牵连。

安全标准：行规是啥？ (了解)

为了衡量一个数据库系统"安不安全"，国际上有一些评估标准。

  • TCSEC（橘皮书）： 美国国防部发布的老标准，把安全等级分成D、C1、C2、B1、B2、B3、A1七级，级别越高越安全。
  • IT安全通用准则（Common Criteria，CC）： 国际标准，从EAL1到EAL7共七级，评估的严谨性逐级增高。

这些标准就像给安全系统打分的"尺子"，帮助大家判断一个数据库系统到底有多"结实"。

4.2 数据库安全性控制 必考

数据库安全性控制模型：多层防护

数据库的安全保护是多方面的，就像给金库设置多道关卡：

  • 用户身份鉴别： 确认"你是谁？"（第一道门卫）
  • 存取控制： 确认"你能干啥？不能干啥？"（进入后的权限）
  • 视图机制： 让你只看到部分数据，敏感信息藏起来。
  • 审计： 记录所有操作，事后可查。
  • 数据加密： 给数据穿上"迷彩服"。

4.2.1 用户身份鉴别：先问"你是谁？"

这是进入数据库系统的第一步，验证你的身份。

  • 静态口令鉴别： 最常用（如密码），但安全性相对低，容易被猜。可以结合"二次验证"（比如手机验证码）提高安全性。
  • 动态口令鉴别： 每次登录密码都不一样（如短信验证码、动态令牌），安全性更高。
  • 生物特征鉴别： 通过指纹、虹膜、人脸等独有特征认证，安全性很高。
  • 智能卡鉴别： 使用带有芯片的智能卡进行验证，通常配合PIN码使用。
  • 入侵检测： 像个"安全警报器"，实时监控可疑行为，发现问题立刻报警或阻断。

4.2.2 存取控制：再问"你能干啥？"

在你被确认身份后，存取控制会限制你对数据库对象（如表、列）的操作权限。

主要两种方式：

  • 自主存取控制 (DAC)：

    特点："自己的地盘自己做主"。你可以把你的权限转授给别人。

    比如，你创建了一张表，你可以决定小王能看、小李能改。这个权力甚至可以"传递"下去。

    优点： 灵活方便。

    缺点： 容易"权限泛滥"，难以管理。

  • 强制存取控制 (MAC)：

    特点："国家规定，强制执行"。数据和用户都有"密级"，你只能访问和你密级相符的数据。你不能随便转授权限。

    比如，一份文件是"绝密"，只有拥有"绝密"权限的人才能看。你即使是看这份文件的"绝密"人员，也不能把它分享给只有"秘密"权限的人。

    优点： 安全性极高。

    缺点： 不灵活，管理复杂。

DAC是"灵活授权"，MAC是"严格管控"。

4.2.3 自主存取控制方法：DAC的核心机制 必考核心

自主存取控制(DAC)通过SQL的GRANT和REVOKE语句实现，管理用户对数据库对象的操作权限。

数据库对象权限表
对象类型 对象 操作类型
数据库和模式 数据库和模式 CREATE
基本表 CREATE TABLE, ALTER TABLE
视图 CREATE VIEW
索引 CREATE INDEX
数据 基本表和视图 SELECT, INSERT, UPDATE, DELETE, REFERENCES, ALL PRIVILEGES
属性列 SELECT, INSERT, UPDATE, REFERENCES, ALL PRIVILEGES

权限由两部分组成：数据库对象（如表、视图）和操作类型（如SELECT、INSERT）。

4.2.4 授权与收回对数据的操作权限 必考核心

GRANT语句用于授予权限，REVOKE语句用于收回权限。

GRANT授权语句

基本语法：

GRANT语法
GRANT <权限> [,<权限>]... ON <对象类型> <对象名> [,<对象类型> <对象名>]... TO <用户> [,<用户>]... [WITH GRANT OPTION];

授权示例：

授权操作示例
-- 把查询Student表权限授给用户U1 GRANT SELECT ON TABLE Student TO U1; -- 把对表SC的查询权限授予所有用户 GRANT SELECT ON TABLE SC TO PUBLIC; -- 把对表SC的INSERT权限授予U5，并允许U5再授予他人 GRANT INSERT ON TABLE SC TO U5 WITH GRANT OPTION;

REVOKE收回权限

基本语法：

REVOKE语法
REVOKE <权限> [,<权限>]... ON <对象类型> <对象名> [,<对象类型> <对象名>]... FROM <用户> [,<用户>]... [CASCADE | RESTRICT];

收回权限示例：

收回权限操作示例
-- 收回U4修改学生学号的权限 REVOKE UPDATE(Sno) ON TABLE Student FROM U4; -- 收回所有用户对表SC的查询权限 REVOKE SELECT ON TABLE SC FROM PUBLIC; -- 收回U5对SC表的INSERT权限（级联收回） REVOKE INSERT ON TABLE SC FROM U5 CASCADE;

注意： 使用CASCADE选项会级联收回用户转授出去的权限，而RESTRICT选项在有转授权限时不允许收回。

4.2.5 数据库角色 重要

数据库角色是被命名的一组权限的集合，用于简化权限管理。

角色操作步骤：

  • 创建角色： CREATE ROLE <角色名>
  • 给角色授权： GRANT <权限> ON <对象> TO <角色>
  • 将角色授予用户： GRANT <角色> TO <用户>
  • 收回角色权限： REVOKE <权限> ON <对象> FROM <角色>

角色使用示例：

角色管理示例
-- 1. 创建角色R1 CREATE ROLE R1; -- 2. 授予R1在Student表上的SELECT、UPDATE、INSERT权限 GRANT SELECT, UPDATE, INSERT ON TABLE Student TO R1; -- 3. 将角色R1授予多个用户 GRANT R1 TO 王平, 张明, 赵玲; -- 4. 收回王平的角色R1权限 REVOKE R1 FROM 王平;

优势： 使用角色可以一次性管理多个用户的权限，当权限变更时只需修改角色权限，所有拥有该角色的用户权限自动更新。

4.2.6 强制存取控制方法：MAC机制

强制存取控制(MAC)为每个数据对象和用户分配敏感度标记，基于规则控制访问。

MAC核心规则：

  • 下读规则： 主体许可证级别 ≥ 客体密级时才能读取
  • 上写规则： 主体许可证级别 ≤ 客体密级时才能写入
密级标记 级别 说明
绝密 (Top Secret, TS) 最高 最高机密级别数据
机密 (Secret, S) 高 高度敏感数据
可信 (Confidential, C) 中 一般敏感数据
公开 (Public, P) 低 可公开访问数据

强制存取控制就像一个"安全等级制度"：低级别人员不能查看高级别文件，高级别人员也不能随意修改低级别文件。

4.3 视图机制与安全性 重要

视图：给你看"定制版"数据

视图是一个"虚拟表"，它自己不存储数据，只是存储了定义它的查询语句。在安全方面，它能很好地隐藏敏感信息。

  • 隐藏敏感数据： 只给用户看他们能看的部分数据（行或列）。

    比如，财务部的工资表很敏感，我们可以创建一个视图，只显示员工姓名和部门，把工资藏起来，给普通员工看这个视图。

  • 简化权限管理： 对于复杂的查询结果，可以先创建视图，再对视图授权，而不是直接对多个基本表逐一授权。

示例：用视图藏工资

假设 Employee 表有敏感的 Salary（工资）信息。

SQL Code (概念性示例)
-- 创建一个视图，只显示员工姓名和部门 CREATE VIEW EmployeePublicView (EmpName, Department) AS SELECT EmpName, Department FROM Employee; -- 把这个视图的查询权限授予用户U1 GRANT SELECT ON TABLE EmployeePublicView TO U1;

效果： 用户 U1 只能看到员工姓名和部门，无法看到工资。就像给敏感信息打了"马赛克"。

4.4 审计 重要

审计：给数据库装个"摄像头"

审计就是DBMS自动记录用户对数据库的所有操作（谁、何时、何地、做了什么），并把这些记录存入审计日志。

就像在你家金库里装了个全天候的监控，所有进出和操作都有记录，方便事后回溯。

主要作用：

  • 监控： 了解数据库使用情况，发现异常。
  • 追溯： 万一出问题，可以倒查原因，追究责任。
  • 合规： 满足法律法规要求（比如金融、医疗行业）。

注意：开启审计会增加系统开销，所以通常只对重要操作或敏感数据进行审计。

示例：开启审计（概念）

不同数据库开启审计的语法略有不同，但原理相似。

SQL Code (Conceptual Example)
-- 开启对SC表的查询操作审计 ENABLE AUDIT ON SC FOR SELECT; -- 开启对Student表的更新和删除操作审计，无论成功失败都记录 ENABLE AUDIT ON Student FOR UPDATE, DELETE WHENEVER SUCCESSFUL OR NOT;

说明： 这就像你在家里安装了摄像头，可以设置只记录客厅的动静，或者记录所有进出门的人。

4.5 数据加密 了解

数据加密：给数据穿"迷彩服"

数据加密就是把可读的"明文"数据，通过算法变成不可读的"密文"，防止未经授权的查看。

  • 存储加密： 数据存在硬盘里时就加密，防止硬盘丢失数据泄露。
  • 传输加密： 数据在网络上传输时加密，防止被"窃听"。

加密算法分两种：

  • 对称加密： 加解密用同一把"钥匙"。速度快，但"钥匙"怎么安全给对方是问题。（如AES）
  • 非对称加密： 加解密用一对"钥匙"（公钥和私钥）。更安全，公钥可公开，私钥自己藏好。速度慢，常用来安全地交换对称密钥。（如RSA）

加密能大大提高数据安全，但会增加一些性能开销。

4.6 其他安全性保护 了解

推断控制：防你"猜"到秘密

主要针对统计数据库，防止用户通过一系列合法查询，反推出敏感的个体信息。

比如，你只能查班级的平均分，但如果班里只有一个男生，你一查"男生平均分"，就直接知道那个男生的分数了。推断控制就是防这种"曲线救国"的查询。

数据库备份与恢复：数据后悔药

当数据库因故障、误操作或恶意攻击导致数据丢失或损坏时，可以通过备份恢复到之前的状态，确保数据的可用性和完整性。

就像你给重要文件做了多份拷贝，即使原件损坏，也能从拷贝恢复，防止数据"彻底消失"。

数据库防火墙：专属门卫

一种专门保护数据库的安全设备，能实时监控和过滤数据库流量，识别并阻止SQL注入等攻击。

它比普通防火墙更"懂"数据库语言，能更精准地拦住针对数据库的攻击，就像给金库大门加了一个专业的安检系统。
