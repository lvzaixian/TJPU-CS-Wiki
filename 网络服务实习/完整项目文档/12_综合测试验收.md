# 综合测试验收

本文档提供完整的测试验收流程，用于验证所有实验内容的正确性。

## 一、Server1 自检（基石测试）

**目的**：确保 Server1 自身没有问题，否则后续测试无法进行。

**操作位置**：Server1 终端

### 1. 检查 IP 与域连接

```bash
ip addr show | grep 192.168.1.100
sudo net ads testjoin
```

**预期**：IP 正确，返回 **Join is OK**。

![域连接测试](assets/image-20260110164034811.png)

### 2. 检查服务状态

```bash
systemctl is-active smbd nmbd vsftpd nfs-kernel-server
```

**预期**：四个服务全显示绿色 **active**。

![服务状态](assets/image-20260110164109837.png)

## 三、Web 与 NFS 集成测试（验收闭环）

**操作位置**：Server2 (Web服务器 192.168.1.101)

**目的**：验证 Server1 的文件是否真的通过 NFS 喂给了 Server2，且 Admin 修改的网页是否生效。

> 此测试验证 **内容 5（NFS 应用）** 和 **内容 6（Web 发布）**

### 1. 验证 NFS 挂载

```bash
df -h | grep 192.168.1.100
```

**预期**：显示 `192.168.1.100:/srv/share/www_root` 挂载在 `/var/www/html`

![NFS 挂载验证](assets/image-20260110181645767.png)

> **📸 截图意义**：证明 NFS 搭建成功

### 2. 验证 Web 内容 (HTTP)

```bash
curl localhost/index.html
```

![Web 内容验证](assets/image-20260110181922278.png)

**意义**：这一步同时证明了：
1. NFS 读取成功
2. Web 服务运行正常
3. 权限设置正确（Web 服务器作为 Others 能读到 Admin 的文件）

## 六、测试执行建议

**推荐执行顺序**：

1. 先在 **Server1** 跑第一节（确保存活）
2. 然后在 **Server2** 跑第三节的第 1 步（确保挂载好了）
3. 最后在 **Client3 (Windows)** 跑第二节（一次性把权限测完）

> 这套方案跑下来，熟练的话 **5 分钟** 就能把所有关键得分点验证完毕。
